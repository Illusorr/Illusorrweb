CTA system · reference build · proposal, not yet adopted

One button, four intents, three sizes, two themes

Nothing on the site loads this sheet yet. It is a proposal: main.css still carries the rules below, and adopting the system means working through the migration table one page at a time. Everything on this page is live and interactive, so the proposal can be judged before any of it ships.

Every CTA on the site currently comes from one of fourteen separate rules in main.css. Padding runs from 6/12 to 17/34, type from 10px to 12px, and hover does something different in almost every one: .cta-primary empties out to transparent, .fakebtn fills with indigo and lifts, #aboutRoot .close .cta swaps white for indigo, .il-talk jumps straight to a flat fill.

This sheet is the replacement. A button reads its theme from an ancestor, never from a variant class, so identical markup works in a dark and a light section. Both hooks are honoured: section.light, which the site already uses, and [data-btn-theme="light"] for anywhere that is not a section.

Dark

the default. --bg #05060a

01 · Primary

A page's single most important action. Solid indigo, white ink, and deliberately the same in both themes so one intent cannot read as two different buttons.

02 · Ghost — the default choice

Outline that fills on hover. This is .fakebtn's behaviour, kept because it was the most used and the best of the fourteen.

03 · Inverse — over imagery

For photography and video, where neither palette is reliable because the ground is a picture. What .il-talk and .vembed-cta were each solving alone.

04 · Quiet + icon

Tertiary text with a hit area, replacing bare coloured text with no affordance. Icon buttons are 44px, not the old 38.

05 · Chip — filters and toggles

Not a call to action: lower case, no tracking, and it carries a selected state through aria-pressed. Replaces three different sizes of the same idea.

06 · In context

A group is laid out with gap, never with margins on the buttons, so the set survives a reorder or a deletion. Under 430px an .il-btns--fit pair stacks full width rather than truncating.

Light

same markup. --cream #ffffff

01 · Primary

Unchanged from dark. That is the point: the most important action on the page looks the same wherever it sits.

02 · Ghost — the default choice

The hairline and the ink move from --cold to --indigo, because a pale blue outline is not legible on white. The fill on hover is identical.

03 · Inverse — over imagery

Identical in both themes by definition. It answers to the picture behind it, not to the section.

04 · Quiet + icon

Quiet resolves to indigo and hovers to --cream-ink, the mirror of the dark board's move to --ink.

05 · Chip — filters and toggles

Selected goes to solid indigo with white ink, rather than the dark board's --cold on near-black.

06 · In context

The same two-button group, unedited. No light variant classes anywhere in the markup.

Do this incrementally. Add buttons.css after main.css, convert one page, confirm it, then move on. The old rules can stay in place until the last page is converted, because nothing in the new system reuses their class names. Note that .fakebtn, .wf-all, .cta-primary and .cta-ghost were already unified in main.css on 7 Sep: they share one stroke, one ink rule and one hover, and all clear 44px. That work is not undone by adopting this system, but it does mean the fourteen-rules problem this sheet describes is now smaller than it states.

Decisions worth knowing before you change them

  • Primary is identical in both themes. Indigo against white is 4.6:1, which clears the 4.5 floor at this size. Making it white-on-dark and indigo-on-light, as the old set did, means one intent reads as two buttons.
  • Theme comes from an ancestor, never a class on the button. A --light modifier has to be applied by hand at every call site and is silently wrong the moment a section changes colour.
  • The state classes share their declarations with the real pseudo-classes through :is(), so this sheet cannot document a hover that behaves differently in the browser.
  • 44px minimum, always. sm is 38px for a mouse and grows to 44 under html[data-touch]. The old .rail-btn and .chipset span were both under the floor on a phone.
  • The arrow is part of the component, set with data-arrow, so no page has to remember to type ↗ and none of them can drift to a different glyph. It shares ::after with the quiet underline, so a quiet button cannot show both.
  • Groups use gap, never margins on the buttons, so a set survives reordering or deleting a button.
